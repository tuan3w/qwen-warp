```python
def merge_intervals(intervals: list[list[int]]) -> list[list[int]]:
    """Merge overlapping intervals in a list of [start, end] pairs."""
    if not intervals:
        return []
    
    # Sort by start time
    intervals.sort(key=lambda x: x[0])
    
    merged = [intervals[0]]
    for current in intervals[1:]:
        last = merged[-1]
        if current[0] <= last[1]:
            # Overlapping: extend the end if needed
            last[1] = max(last[1], current[1])
        else:
            merged.append(current)
    
    return merged
```

Think of your CPU as a super-fast chef and your main memory (RAM) as a distant warehouse. The CPU cache is essentially a small, high-speed counter right next to the chef where they keep the ingredients they are currently using. Because the counter is right there, the chef can grab an ingredient instantly, whereas going to the warehouse takes a lot of time. This speed difference is crucial because the CPU processes data much faster than it can retrieve it from RAM.

To make this work, the system uses a strategy called "locality of reference." It assumes that if the CPU accesses a specific piece of data, it is likely to access nearby data soon. So, when the CPU requests one item, the system loads a whole block of related data into the cache at once. This way, if the CPU needs the next item in the sequence, it’s already sitting on the fast counter, ready to be used without waiting for the slow warehouse trip.

However, this counter has limited space, so it can’t hold everything. When it gets full, the system has to decide what to throw away to make room for new data, a process known as cache eviction. If the CPU needs data that was just thrown out, it has to go back to the slow RAM to fetch it again, causing a "cache miss." Programmers write code with this in mind, structuring data so that frequently used items stay close together, ensuring the cache stays full of useful information and the CPU runs as fast as possible.

```sql
WITH customer_totals AS (
    SELECT
        c.country,
        c.customer_id,
        c.customer_name,
        SUM(o.order_value) AS total_order_value
    FROM customers c
    JOIN orders o ON c.customer_id = o.customer_id
    GROUP BY c.country, c.customer_id, c.customer_name
),
ranked AS (
    SELECT
        country,
        customer_id,
        customer_name,
        total_order_value,
        RANK() OVER (PARTITION BY country ORDER BY total_order_value DESC) AS rnk
    FROM customer_totals
)
SELECT
    country,
    customer_id,
    customer_name,
    total_order_value
FROM ranked
WHERE rnk <= 3
ORDER BY country, rnk;
```

**Explanation:**

1. **`customer_totals` CTE**: Joins `customers` and `orders`, then groups by country and customer to compute each customer's total order value within their country.

2. **`ranked` CTE**: Uses the `RANK()` window function partitioned by `country` and ordered by `total_order_value` in descending order. `RANK()` (rather than `ROW_NUMBER()`) is used so that ties in total order value are all included, ensuring no customer is arbitrarily excluded if multiple customers share the same top value.

3. **Final `SELECT`**: Filters to only the top 3 ranks per country and orders the results by country and rank for readability.

> **Note:** Adjust table and column names (`customers`, `orders`, `customer_id`, `order_value`, `country`, `customer_name`) to match your actual schema. If you want exactly 3 rows per country even with ties, replace `RANK()` with `ROW_NUMBER()`.
