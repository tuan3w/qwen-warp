# swift-mk engine: contract

Goal: fastest single-stream decode of Swift-1.5-Qwen3.8-27b-INT4 on one RTX 3090 (sm_86, CUDA 13.0, nvcc -arch=sm_86 -O3, no PDL, no TMA).
Evidence behind the design (all in `experiments/2026-10-30-*`):
- E1: a CUDA graph of per-op kernels is within 2.5% of a persistent kernel for the GEMV chain -> **CUDA graph of fused kernels**, not a persistent kernel (persistent stays an optional last step).
- E3: W4A16 mma GEMV (`experiments/2026-10-30-w4-multirow-verify-and-power/kernels.cuh`, clean-room, reuse freely) verifies T=4 rows for +2-5% over T=1 and is 4-7% faster than CUDA-core at T=1 (keep CUDA-core for BF16 lm_head).
- E0/E3: stock vLLM = 46.8 tok/s plain, 96 with MTP k=3 on code; the draft step (BF16 MTP layer + full 248k lm_head) is the biggest recoverable cost -> engine needs int4 MTP layer + restricted-vocab draft head (E4 measures acceptance).
- Semantics ground truth: `oracle/` (`NOTES.md` has every tensor/shape/gotcha; `reference.py` CPU decoder; dumps in `~/llm-lab/swift-ref/{fp32,bf16}/{code,prose,math}.pt`, layout in `docs/OVERVIEW.md`).

## Layout (project `engine/`)
- `include/*.h` public C API (`extern "C"`, raw device pointers + `cudaStream_t`, no torch types), `src/*.cu`, `tests/test_*.py` (ctypes into `build/libswiftmk.so` + torch tensors from the lab env `~/llm-lab/venv/bin/python`, compared against the oracle), `Makefile` (`make` builds `build/libswiftmk.so`; each agent adds its own .cu to SRCS, keep merges trivial: one source list line per file).
- Only clean-room code: open-jet is AGPL (design reference only); bonsai-turbo / lucebox (Apache-2.0) may be adapted with attribution in the file header.

## Conventions (fixed so independent kernels compose)
- Activations bf16, row-major `[T][dim]`, T <= TMAX rows per step (row t = token at position pos0+t; T=1 plain decode, T=1+k verify); K11: step buffers hold SMK_TMAX = 8 rows, the engine's `tmax` (4 default, 8 with `SMK_TMAX=8` / `Engine(tmax=8)`) bounds T. Residual stream bf16, math fp32 inside kernels.
- Weights W4: uint32 `[N][K/8]` (nibble e of word j = column 8j+e, value (n-8)*scale), bf16 scale `[N][K/128]`, groups = contiguous 128 (no g_idx in this checkpoint) = the checkpoint-natural layout (packer output, `smk_w4_gemv`, oracle tests). **K12: the engine, MTP, quantised-head and prefill kernels read the REPACKED layout** (`pack.repack_w4`, `smk_w4r_gemv`, `smkp_w4r_gemm`, `smkp_dequant_w4r`; `include/engine.h`): per (16-row tile, 128-k group) one contiguous 1 KB unit, nibble j / j+4 of a word = columns 2j / 2j+1, scale = one u32 (bf16 row g | bf16 row g+8 << 16) per (tile, group, g); same tensors and byte counts, converted IN PLACE by `Engine` / `SpecEngine` after loading (`W4.repack()`), so anything that reads packer outputs after constructing an Engine sees the repacked layout (tests that need the natural layout use the packer directly). The repacked kernels are NOT bit-identical to the natural ones (the k order inside 8 columns differs; ~1e-5..2e-4 of the outputs differ by 1 bf16 ulp): `tests/test_w4r.py`.
- DeltaNet state: fp32 `[slot][48 v-heads][128 V][128 K]` (vLLM layout [H,V,K]; HF oracle uses [H,K,V]: transpose when comparing), conv state bf16 `[slot][10240][3]` (last 3 raw inputs). Slots per layer: ring of tmax+1 = 5 (tmax 4) or 9 (tmax 8, K11: +0.62 GiB). Per step the engine holds a device int `cur` per sequence: a step reads slot `cur`; row t writes its post-state to slot `(cur+1+t) % 5`; after the verifier accepts `a` rows (1..T), `cur = (cur + a) % slots` (no copies, rollback is free). **K12 lazy snapshots (`include/deltanet.h`, `swiftmk_deltanet_step_lazy`): a T >= 2 step does NOT write its per-row post-states; it appends their rank-1 updates to a per-layer delta buffer (`dn_dbuf`, `SWIFTMK_DN_LAZY_ROWS` rows) and the device scalar `ds[DS_PEND] = p | base << 8 | half << 12` says the state at slot `cur` is "slot `base` + the first `p` delta rows" (`p == 0`: slot `cur` itself).** Whoever advances `cur` (`k_advance`, the accept kernels) updates it with `dn_pend_after` (`engine_impl.h`); a T == 1 step writes a full snapshot and sets it to 0; the next step replays the pending rows bitwise like the recurrence. **Anything that reads or writes the ring from outside the graphs (snapshot, prefill, a host-side restore) must first call `smkp_materialize` / `swiftmk_deltanet_materialize` (writes the pending state to slot `cur`, clears `ds[DS_PEND]`); a host-side RESTORE that overwrites slot `cur` must set `ds[DS_PEND] = 0` itself (server `smk_runner._restore`).** `smk_spec_snapshot` / `smk_engine_reset` / `FastPrefill._run` do this.
- Full-attention KV: `[16 layers][2][4 kv heads][ctx][256]`, written positionally (rows write pos0+t; unaccepted rows are overwritten next step; no rollback). dtype template: bf16 or fp8 e4m3 with the checkpoint per-layer `k_scale`/`v_scale` (value_fp8 = x / scale, dequant x*scale). Causal mask inside the T-row block. GQA: 24 q heads / 4 kv heads.
- Norms: RMSNorm `x * rsqrt(mean(x^2)+1e-6) * (1+w)` (zero-centered) everywhere except the DeltaNet gated norm (plain `w`). See NOTES.md for q|gate interleave, rope (64 of 256 dims, theta 1e7, text-only so mrope == plain rope), head repeat (k head h//3 feeds v heads 3h..3h+2).
- Every kernel API takes `cudaStream_t` and is capturable in a CUDA graph (no host sync, no dynamic allocation, device-side scalars for pos/cur/ctx_len so one captured graph serves every step).

## Kernel APIs owned by each agent
- **K1 DeltaNet** (`include/deltanet.h`): per layer, T rows: inputs `qkv[T][10240]` (q2048|k2048|v6144), `z[T][6144]`, `a[T][48]`, `b[T][48]` (the BF16 in_proj_a/b outputs, computed elsewhere), weights `conv_w[10240][4]`, `A_log[48]`, `dt_bias[48]`, `norm_w[128]`; state slots as above; output `y[T][6144] = RMSNorm_gated(o; w) * silu(z)` ready for out_proj. Steps per row: causal conv1d (taps over [3 stored inputs + current]) + SiLU on q,k,v; L2-norm q,k (eps 1e-6), q *= 128^-0.5; g = -exp(A_log)*softplus(a+dt_bias), beta = sigmoid(b); S = S*exp(g); kv = S k; d = (v-kv)*beta; S += d (x) k; o = S q. Spread over ALL 82 SMs (parallel over v-head x V-slice), rows sequential inside; one launch (conv+gating+recurrence+norm fused if you can prove it). Target: state traffic ~(1+T) x 151 MB per step at >= 700 GB/s.
- **K2 attention** (`include/attn.h`): per full-attention layer, T rows: inputs `q_proj[T][12288]` ([q|gate] interleaved per head), `k[T][1024]`, `v[T][1024]`, weights `q_norm[256]`, `k_norm[256]` (zero-centered), positions pos0 (device scalar), ctx_len after write; per-head q/k RMSNorm, partial rope, KV write, split-KV flash-decode (all SMs, two-stage reduce, ctx up to 32K) with in-block causality, `o *= sigmoid(gate)`; output `[T][6144]` ready for o_proj. Same code serves the MTP layer's attention (separate KV cache).
- **K3 engine core** (`include/engine.h`): weight packer (checkpoint -> engine buffers, incl. fused [qkv|z], interleaved gate|up for the SiLU*mul epilogue, in_proj_a/b BF16 small GEMV, bf16 lm_head, embed gather), RMSNorm (+fused residual add), W4 mma/CUDA-core GEMV launchers (T=1..4), SiLU*mul, lm_head + argmax (and top-k), the 64-layer step wired to K1/K2 APIs, CUDA-graph capture, host driver for prefill-by-decode (slow is fine) and greedy decode; validation against the oracle dumps layer by layer then end-to-end token ids.
- **K4 speculative decoding** (`include/mtp.h`, `src/mtp.cu`, `pack_mtp.py`, `spec.py`; numbers in `engine/BENCH.md`): int4 MTP layer + restricted-vocab (64k) int4 draft head packed offline from the BF16 checkpoint; one CUDA graph per cycle = verify (T=1+k rows, full BF16 lm_head for every row) + on-device greedy accept (cur / conv ring / pos / anchor / output ring as device scalars) + MTP catch-up of the accepted rows + k chained drafts. Greedy (`temperature == 0`). Tests: `tests/test_mtp.py`, bench: `tests/bench_spec.py`.
- **K7 sampling + exact speculative sampling** (`include/mtp.h` section K7, `src/mtp_sample.{h,cu}`, `spec.py` `set_sampling`; numbers in `engine/BENCH.md`, experiment `experiments/2026-10-31-spec-sampling-exactness/`): `smk_spec_set_sampling` with temperature > 0 switches the cycle / start / plain decode to the sampling graphs (same structure; the greedy graphs are untouched). Target distribution per verify row = logits/T -> top-k (<= 64) -> top-p -> softmax over the survivors (HF/vLLM order), computed in-graph by a 3-kernel device top-k (chunk maxima, thresholded block top-k, shared-memory K-way merge) over the fp32 logits of the 1+k rows; drafts are sampled from q = the same processing of the restricted-vocab draft head logits (or q = delta at the argmax: `draft_sample = 0`); acceptance min(1, p/q), residual max(0, p-q)/Z on rejection, bonus token from p: the emitted stream is distributed exactly as autoregressive sampling from p. philox4x32-10 RNG, counter = device cycle counter (seeded, reproducible, no host sync). `smk_spec_sample_first` samples the first token from the last prompt row's logits (call before `smk_spec_start`; `FastPrefill.prefill_spec` does). Tests: `tests/test_sampling.py`.
- **K8 server** (`server/`, README there): vLLM 0.30's own OpenAI frontend (`AsyncLLM`) on an in-process swift-mk `EngineCoreClient` (`smk_core_client.py`) + engine driver (`smk_runner.py`: fast prefill, k <= 3 MTP cycles, K7 sampling, exact stops, DeltaNet snapshots for multi-turn prefix reuse); `serve.py` or the `vllm.general_plugins` entry (`VLLM_SWIFT_MK=1 vllm serve`).  bs = 1, FIFO.  Tests `smoke_test.py` / `runner_check.py`, numbers in `engine/BENCH.md`.
- **K9 quantised lm_head + exact rescoring** (`include/head_q.h`, `src/head_q.cu`, hooks in `src/engine.cu` `head_tail` and `src/mtp.cu`, packer `pack.py` `quant_head_i8/i4`, `Engine(head="int4"|"int8"|"bf16")` / env `SMK_HEAD`; numbers in `engine/BENCH.md` K9, experiment `experiments/2026-10-31-lm-head-quant-engine/`): the head step of every plain / verify / sampling graph computes approximate logits of all 248320 rows from a quantised copy of the BF16 head (int8 per-row fp32 scale, CUDA-core kernel; or int4 g128 RTN in the engine W4 layout via `smk_w4_gemv_cfg` 1 + `SMK_EPI_F32`; quantised on the GPU at load from the BF16 head, ~1 s, no cache file), selects the exact top-R of them per row (R = 16 greedy, 64 when sampling is configured: the device top-k <= 64 then sees exact logits), recomputes those R logits exactly from the resident BF16 head (fp32 accumulate over exact bf16 products) over the approximate ones in the logits buffer and takes the argmax over the exact candidates -> `ds[DS_OUT]`.  The argmax is the BF16 head's whenever the BF16 top-1 is among the candidates (19976 real hidden states: always, 1 exact-fp32-tie order flip).  `Engine.set_head("bf16"|"q")` / `smk_engine_set_head` switches back to the plain BF16 head (A/B in one process; drops the cached graphs).  The 64k int4 draft head is unchanged.  Costs VRAM: +0.59 GiB (int4) / +1.18 GiB (int8) on top of the BF16 head that must stay resident.

- **K10 short-prompt prefill** (`src/prefill_w4.cu`, `prefill.py` `FastPrefill(w4_max, fold)`, `server/smk_runner.py`; numbers in `engine/BENCH.md` K10): multi-row W4 mma GEMM (T <= 64 rows per call, bit-identical to the decode GEMV) replaces dequant + cuBLAS for prompts <= 240 tokens; the last prompt row rides in the final batch (decode-kernel DeltaNet row + `smk_engine_head_tail`).  Tests `tests/test_w4mm.py`, `tests/test_prefill.py`, bench `tests/bench_short_ttft.py`, `server/bench_ttft.py`.
- **K11 hybrid draft = MTP chain + prompt-lookup tail** (`include/pld.h` + `src/pld.cu` host n-gram proposer, `include/mtp.h` K11 section + `src/mtp.cu` `smk_spec_run_pld`, T <= 8 kernels in `src/deltanet.cu` / `src/attn.cu` / `src/head_q.cu`, `spec.py` `enable_pld` / `cycles_pld`, `server/` `--prompt-lookup`; numbers in `engine/BENCH.md` K11, experiment `experiments/2026-11-01-pld-tail-engine/`): E6's best cell (n = 2 longest suffix of the chain, agreement >= 3, tail <= 4 tokens appended after d1..d3) verified as T = 4 + tail = 7 / 8 rows in one per-width CUDA graph; the host picks the width per cycle from a mapped-memory mailbox written by the previous graph (< 10 us gap).  Greedy = leading match, sampling = K7 with delta proposals (accept w.p. p(d), residual p without d).  `Engine(tmax=8)` / env `SMK_TMAX=8` allocates the 9-slot DeltaNet ring (+0.62 GiB); the default stays tmax = 4 (5 slots, no cost, T <= 4 steps only).  Measured: V(8) = 21.6 ms (V(4) 19.6), E6 workload a-c x1.38 greedy / x1.36 sampling, d x1.01, e x1.07.  Tests `tests/test_pld.py` (proposer == E6's simulation), `test_pld_engine.py` (greedy parity, rollback up to 8 rows, ring wraps, forced-tail sampling), `test_sampling.py trials-pld`, bench `tests/bench_verify.py`, `tests/bench_pld.py`.

## Rules
- Pre-register nothing here (engineering, not experiments), but every kernel needs a unit test with a stated tolerance vs the oracle/torch reference and a micro-benchmark number (GB/s, ms) recorded in `engine/BENCH.md` (append, with date, GPU clocks).
- The GPU is a single shared 3090: `projects/llm-lab/bin/lab gpu acquire` / `release` around runs, never hold it while idle; other agents (a long vLLM experiment may hold it for an hour+: wait and retry, build/compile meanwhile).
- Disk ~3 GB free: no big temp files; builds only under engine/build.
