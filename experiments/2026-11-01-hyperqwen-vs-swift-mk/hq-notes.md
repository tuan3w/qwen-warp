## 1. Architecture summary
HQ is not an engine: it is a pinned vLLM 0.30.0 wheel + a 45-patch series (hq:PATCHES.md:12-66, hq:patches/series) + KVarN backend port (hq:kvarn/README.md:1-30)
+ a CPU-only model-prep pipeline (prepare/) + launchers (single-user/start_qwen.sh, batch/start_qwen.sh) + a docker wrapper. Target = a community W4A16 AutoRound
compressed-tensors checkpoint (`dbirks/Qwen3.8-27B-W4A16-AutoRound`, hq:docker/prepare.sh:15) whose lm_head/embed_tokens (2.5 GB bf16 each) and MTP module (850 MB bf16) are requantized
(int8, or int4-GPTQ in the "fast variant"); GDN recurrent state is fp16 (`--mamba-ssm-cache-dtype float16`, hq:single-user/start_qwen.sh:833). Single-user mode = vLLM V1/V2 runner
(V2 forced for DFlash2) with chunked prefill 2048 (`--max-num-batched-tokens 2048`, :835), CUDA graphs, async-scheduling, speculative decoding by MTP (k=4/3) or a DFlash2 block drafter
(7 drafts/pass, 1.19 GB W4A16) fused with an on-GPU suffix-lookup drafter that can extend the verify block to 16 tokens, optional prefix caching of hybrid (GDN) state, selectable KV dtype
(bf16 / fp8 / int8-per-token-head / int4 / KVarN 4-2 bit). Batch mode drops speculation and uses Marlin W4A8 (int8 activation) GEMMs. Everything is exact-by-construction w.r.t. its own
(quantized) target. [C] Headline: 127 tok/s C1, 381 tok/s quoting, ~1,035 tok/s @64 (hq:README.md:24-28).

## 2. Speculative method per mode

### 2a. MTP (`SPEC=mtp`, launcher default) [C]
- k: `DRAFT_TOKENS` 4 for CTX=fast, 3 for long/huge (hq:single-user/start_qwen.sh:193-207); k=5/6 slower (hq:single-user/README.md:286,293; optimizations.md:399). k=4 on FlashInfer (fp8 KV) crashed on 0.28 (single-user/README.md:310-322; "not re-verified on 0.29/0.30").
- Head: Qwen's own 1-layer MTP module ("single-layer chain drafter at its ceiling", hq:docs/optimizations.md:204-205); no tree: "a tree drafter would [raise acceptance], but the DeltaNet layers can't verify a tree" (hq:single-user/README.md:340-341).
- Precision: base int8; fast variant int4 GPTQ calibrated on target hidden states, 850 -> 215 MB/draft; lm_head int4 GPTQ 1.27 -> 0.65 GB (hq:single-user/start_qwen.sh:14-16). Drafts scored by a 40,960-row slice of lm_head (section 3). `draft_sample_method: probabilistic` (start_qwen.sh:500; "greedy" drafts ~15% slower at T>0, single-user/README.md:295, :429).
- Verify: one multi-query pass (k+1=5 rows); attention = HQ's Triton split-KV kernel (`VLLM_SPEC_DECODE_ATTN=1`, bf16 KV, CTX=fast only; P:spec-decode-attn.patch:1-28) because FA2 gives 24 blocks on 82 SMs (hq:docs/gotchas.md:161-166); sampler = sort-free top-k/top-p for k<=64, multi-block softmax, drafts truncated to target top-k/top-p (P:sampler-small-topk-fast-softmax.patch:1-17).
- Result [C]: 111.1 tok/s default sampling / 120.0 greedy decode at C1, 2.75/2.90 tok/step (hq:single-user/README.md:34). Re-measure on 0.30: 2.89/2.81 tok/step greedy/default (hq:docs/vllm-0.30.md:106). Per-position acceptance 74/50/34/24% (T=1) (single-user/README.md:42).

### 2b. DFlash2 drafter (`SPEC=dflash2`, `.env.example` default; hq:.env.example "SPEC=dflash2 PREFIX_CACHE=1")
- Architecture [C]: 5 Qwen3-style layers (hidden 5120, 8 KV heads x 128, MLP 17408), `fc` projecting target hidden states of layers 5/19/33/47/61, dynamic convs, a candidate selector; 1.92B params; bf16 3.85 GB (hq:drafter/README.md:50-57; optimizations.md:204-211). Own attention window 2,048 tokens (single-user/README.md:124-126). Source: incoai/Qwen3.8-27B-DFlash2 (Inco, Aug 2026), vLLM native since 0.28 via PR #52816 (optimizations.md:213-215).
- Quantisation: GPTQ int4 g128 on the 36 matrices (35 layer matrices + fc), Hessians captured from the drafter's own inputs on 400 prompts (~290k rows/layer; ~56 GB scratch), compressed-tensors W4A16 Marlin, **1.19 GB** (optimizations.md:223-232; drafter/README.md:59-85). int4 costs ~5% acceptance at default sampling (3.2 vs 3.4 tok/step), nothing at greedy; fc bf16 no better; blending ctx-KV Hessian made greedy 7% worse (drafter/README.md:79-84). Drafter shares the target's *quantized* lm_head (optimizations.md:218-219).
- Drafts: ONE non-autoregressive pass proposes **7 tokens** ("block_size 8 = one anchor + 7 mask tokens", optimizations.md:272-275). A selector walks one coherent path through **16 candidates per slot** (optimizations.md:207-209; P:dflash2-lookup-drafting.patch:644-700 `_selector_walk_kernel`). => verification is a **linear chain** block, not a tree.
- Verify: target runs 1+7 = 8 query tokens (or 16 with `DFLASH_TOKENS=15`) in one pass, FLASH_ATTN/bf16 KV with the same Triton split-KV kernel (`VLLM_SPEC_DECODE_ATTN_QMAX = DRAFT_TOKENS+1`, start_qwen.sh:278). One tile holds 128//G = 21 query tokens (G=24/4=6); Marlin M-tile 16 => cost stairs at 16 and 21 query tokens (hq:docs/gotchas.md:252-265 [C]).
- Exactness: greedy emits target argmax whether or not the draft matched ("rejection_sampler.py emits target_argmax", start_qwen.sh:295-297). Sampling: rejection sampling against sparse cached draft logits (-inf outside the 16-candidate support, truncated to the request's top-k/top-p, `VLLM_DFLASH2_DRAFT_TOPK_TOPP`, P:dflash2-lookup-drafting.patch:672-700). Caveat: greedy text is NOT bit-identical across drafter/block configs (hq:gotchas.md:178-182,13; 7 of 9 long greedy prompts identical with LOOKUP=0 vs 1, single-user/README.md:257-259).
- Numbers [C]: 121.8 default / 131.2 greedy decode C1; 3.12/3.34 tok/step; 26.5 ms/step vs MTP 24.8 (single-user/README.md:74,94-96). 0.30 re-measure 3.43/3.28 tok/step (vllm-0.30.md:107). Needs >=1 resident request = 8 recurrent-state slots = 15.8% of the pool => one-user mode: 137/97/46/33 tok/s per stream at 1/2/4/8 streams (single-user/README.md:112-123).
- Hard dependency on a V2 model runner: `_is_dflash2_draft()` forces it (hq:docs/long-context.md:251) and the launcher pins KV in bytes (`KV_MEM`, start_qwen.sh:352-356) because the V2 runner's profiled peak swings ~1 GiB between starts (gotchas.md:189-198).

### 2c. Lookup drafting (`LOOKUP=1`, `patches/dflash2-lookup-drafting.patch`) - how the "15 verified tokens" are built
- At `DFLASH_TOKENS=15` the verify block is 1 bonus + 15 drafts = **16 query tokens** (single-user/README.md:178-179; README.md:105 says "15 tokens verified" - same thing). Positions 0-6 = DFlash2 selector tokens; positions 7-14 = *nothing but the lookup* ("0 cost to the drafter", optimizations.md:277-278). Checkpoint block (7) is clamped by `trained_block = dflash_config.block_size-1` (P:dflash2-lookup-drafting.patch:186-205; gotcha 51, gotchas.md:1132-1136).
- Kernel `_suffix_lookup_kernel` (Triton, 1 program/request, inside the captured draft graph; P:dflash2-lookup-drafting.patch:318-380): searches the request's *whole* token history (prompt + output; `all_token_ids` UVA buffer; `SEARCH`=2^30 tokens), candidate end positions e in [NMIN-1, total-1), reject on NMIN tokens first, extend up to NMAX; score = len*2^32 + end index => **longest match, ties -> most recent**; match may overlap the suffix (period-p repeats). Defaults NMIN=6, NMAX=12 (P:speed-knobs-envs.patch:31-38; hq:single-user/README.md:425). Returns the <=k tokens that follow the match.
- Fuse kernel (P:dflash2-lookup-drafting.patch:389-474): head positions (< draft_block): lookup *replaces* drafter token iff match_len >= NSTRONG (default **6**) [or match >= NMIN and drafter agrees on first AGREE tokens; default AGREE **0**]; tail positions (>= draft_block): taken iff match_len >= NMIN_TAIL (4) and (head taken or drafter agreed through the block); tail always gets a point-mass q. `take_flags` = match_len >= LONGMIN(6) and valid > draft_block and take_tail.
- CONFLICT: optimizations.md:296-298 says NSTRONG is 8 and AGREE 2; code/envs/README say 6 and 0 (P:speed-knobs-envs.patch:33-34; speculator comment P:dflash2-lookup-drafting.patch:782-785 "NSTRONG = NMIN and AGREE = 0 ... measured better").
- Exactness: lookup positions get a point-mass draft distribution (accept prob p(x), residual (p-q)+), greedy never reads q (P:dflash2-lookup-drafting.patch:296-302, 476-510). [C] "GSM8K 96.5% with lookup" (optimizations.md:322).
- Adaptive block length (host side, `next_num_draft_tokens`, P:dflash2-lookup-drafting.patch:858-905): long (16) block scheduled only when per-request flag (from the *previous* step via pinned async copy, one step stale) AND the last step emitted >= 1+draft_block tokens, **two steps in a row** (:892-896); `STICKY`=3 steps coast, single request only (:826-846); batch-wide (all requests must agree). Needs `--no-async-scheduling` (start_qwen.sh:310-316, ~<1% at C1). Decode CUDA graphs captured for both lengths 8 and 16 (P:dflash2-lookup-drafting.patch:78-120; gotchas.md:245-251).
- Costs: 4 request slots and 56k ctx (KV_MEM 5.2 GiB, 57,669-token pool) instead of 8 / 64k, because aligned mamba state pages scale with (k+2): 0.88 GiB at k=7, 1.66 GiB at k=15 (gotchas.md:316-327). Long block only ever fires on copy-like output: on chat prompts positions 7-14 take 72 of 11,069 accepted tokens (0.65%) (single-user/README.md:507-512 [C]; 0 for @changtimwu).
- Difference from OUR PLD tail (ENGINE.md K11, engine/BENCH.md:K11): ours = **host** proposer (C++, 2.9 us), gram = last two chain drafts (d2,d3), needs backward agreement >= 3 over <= 64 most-recent candidates, appends <= 4 tail tokens AFTER d1..d3 (T = 4 + 4 = 8 rows, one graph per width 4/7/8), width chosen from a mapped-memory mailbox (< 10 us gap). HQ's = GPU kernel keyed on the **last 6-12 committed tokens** (no dependence on drafts), can overwrite the drafter's 7 head tokens too, fills up to 15, two graph widths (8/16), gate = 2 consecutive saturated steps via stale async flag. Theirs reaches 15 tok/step on pure copy; ours max 8 rows (a1-a3: 7.7 tok/cycle, 326 tok/s, BENCH K11).

### 2d. ngram chains (`VLLM_DFLASH2_CHAIN=1`, `patches/dflash2-ngram-chains.patch`, off by default) [C]
- Drafter-free steps: while a request keeps reproducing context, whole verify blocks come from `suffix_lookup` alone and the draft model forward + graph replay are skipped until the FIRST rejected token (P:dflash2-ngram-chains.patch:38-70 state, 97-250 propose/_chain_should_engage/_chain_generate). Entry: previous *normal* step's longest match >= MINMATCH (8; capped by NMAX 12); exit on any rejection; one normal step before re-entry; greedy only (`CHAIN_GREEDY_ONLY`=1: "-8% C1 at T=default"), single request, dp=1. All positions point-mass.
- Claimed +7% on copy cell (256.9 -> 276 tok/s at DFLASH_TOKENS=7) (single-user/README.md:488-495). Ported from @Dmtrii-tesla/dflash2-ngram-vllm (#38).
- Related negative result: skipping the drafter on lookup-selected steps lost 6% (gotchas.md:274-284).

### 2e. z-adaptive (`dflash2-z-adaptive-emitted.patch`) [C]
Bug fix to the adaptive controller input: `last_num_emitted = num_sampled` (the emitted count) instead of `num_sampled - num_rejected` which double-counted rejections (num_rejected = num_logits - num_sampled) (P:dflash2-z-adaptive-emitted.patch:5-41; hq:PATCHES.md:26). Only visible on cohorts, not single short prompts (gotchas.md:1132-1146). (The doc never defines "z"; I read it as the adaptive block-length signal.)

## 5. int8 prefill attention and INT8_ACT
- `PREFILL_ATTN=int8` (`VLLM_PREFILL_ATTN=int8`): Triton, QK^T on int8 tensor cores (SageAttention-style): K smoothed by per-(kv-head, channel) context mean (softmax-invariant), gathered+quantized once per layer-chunk in 64-key tiles, Q per-row absmax, P.V bf16 (P:prefill-attn-int8.patch:1-17,108-125).
- **Gate** (P:prefill-attn-int8.patch:62-79): `VLLM_PREFILL_ATTN in (int8,fp16)` AND `max_seqlen_q > 16` AND single request in the varlen batch (`cu_seqlens_q.shape[0]==2`) AND `num_heads == 24 and num_kv_heads == 4 and head_size == 256` AND bf16 KV (`not is_quantized_kv_cache`) AND no sliding window/softcap/alibi/sinks AND causal; else FA2. => our fine-tune (24/4/256) passes; fp8/int8/KVarN KV does not (so CTX=long/huge do not get it). Decode and the split-KV verify untouched.
- Claims [C]: 1.27x FA2 at 4k -> 1.35x at 51k on the attention itself (cos > 0.99999); standalone prefill +0.3/+1.1/+3.3% at 4k/16k/51k (1,167/1,126/1,012 vs 1,164/1,114/980) ; with INT8_ACT +1.8% @16k, +4.5% @51k on top (optimizations.md:152-165). A WSL2 3090 measured standalone 1-6% NEGATIVE (#62).
- `INT8_ACT=int8` (`VLLM_MARLIN_INPUT_DTYPE=int8`) + `INT8_LAYERS` regex (default `mlp|linear_attn|self_attn`, start_qwen.sh:139-142): Marlin W4A8 (weights int4, activations per-token int8, int8 mma) for prefill; default OFF in single mode (decode memory-bound: "122+-5 vs 121 tok/s"). Prefill tok/s at 1k/4k/16k/51k: W4A16 1,437/1,494/1,410/1,200; `mlp` 1,638/1,696/1,587/1,320; all 1,845/1,937/1,791/1,423 (optimizations.md:130-134 [C], seeded protocol). Cost: PPL +4.1% (8.423 vs 8.095), GSM8K 95.0 vs 96.5 (start_qwen.sh:133-138). `mlp|linear_attn` mixed set crashes (inductor bug).
- `--max-num-batched-tokens` 4096/8192 do not boot under pinned KV_MEM (optimizations.md:189-191). SPEC=off / PREFIX_CACHE=0 prefill ~20% slower (:179-188). Marlin tile tuning: +2-20%/GEMM standalone, +0.4% e2e at 250 W (:192-197).
- Ours for comparison: prefill via dequant->bf16 cuBLAS (no activation quantisation), 2,133 tok/s @4K, 2,077 @8K, 2,005 @16K (engine/BENCH.md K6) vs HQ 1,494 (W4A16 default) / 1,937 (int8 act) @4k.

## 6. Marlin int8 layer selection, patches, requantized heads, embed quant
- layer-select (P:marlin-int8-layer-select.patch:1-10,52-66): env `VLLM_MARLIN_INT8_INCLUDE_RE` (default "") / `VLLM_MARLIN_INT8_EXCLUDE_RE` (default `lm_head|mtp`), `re.search` on layer prefix; registered in envs.py so they enter the compile cache key. Batch default `INT8_LAYERS=mlp` (all MLP gate/up/down), `gate_up`, `.` = all linears (batch/README.md:36-41,198; quality.md:26-39).
- negative-scales (P:marlin-int8-negative-scales.patch:1-10,27-56): kernel reads int16-requantized group scales as *unsigned*; AutoRound symmetric exports have ~50% negative scales -> garbage while benchmarking fine (gotcha 1). Fix at load: s->-s, q->-q (uint4b8 code v -> 16-v clamp 15; code -8 loses 1 LSB). Only for act_type int8, g!=-1, no zero-points. [I] Our checkpoint: symmetric g128 W4, no zero points, no g_idx keys [O: checked our index: 0 g_idx, 0 weight_zero_point], so patch applies/needed for INT8_ACT only.
- asym-zp (P:marlin-int8-asym-zp.patch:1-22): admits `uint4` (zero-point) next to `uint4b8` on the int8 path (kS8 x kU4 kernel already compiled).
- Heads: `quant_lm_head.py` / `quant_embed.py` BITS=8 g128 symmetric (hq:prepare/quant_lm_head.py:37, quant_embed.py:37) ~1.3 GB freed each; `quant_mtp.py` MTP module bf16 850 MB -> int8 (mtp.fc + gate/up/down + q/k/v/o, quant_heads_stream.py:60-70); fast variant: lm_head int4 GPTQ (KL 0.0029 vs RTN 0.0068; Hessian from 300k captured hidden states, +0.6% PPL, GSM8K 96.5%) and MTP int4 GPTQ; embed stays int8 (third-party-checkpoints.md:44-49); optional `-emb4` int4 embedding ~+0.6 GB pool (:153-161). ## 7. Hybrid KV / mamba (GDN) / 16-bit state
- fp16 recurrent state: `--mamba-ssm-cache-dtype float16` (config asks fp32 ~150 MB/req); "perplexity unchanged to three decimals" (8.045 -> 8.044); lifts resident requests 37 -> 64 @batch (optimizations.md:54-62 [C], quality.md:32-33). Hidden states from decode differ from prefill ~0.9% (drafter/README.md:114). Ours keeps fp32 state (ENGINE.md "DeltaNet state fp32 [slot][48][128][128]"); [I] our K1 state traffic at T=8 is 2.0 ms of ~21.6 ms step (BENCH K11), so fp16 state would be worth ~1 ms at most - untested.
- hybrid-kv-groups-v2-cudagraph (P:...:1-37): KV groups were sized by the smallest bucket (drafter's 5 SW layers) -> target 16 attn padded to 20 and 48 GDN to 50 (+25% pool); fix picks gcd of non-SW buckets: 105 -> 78 KB/token, pool 45,383 (40k) -> 69,758 (64k) (optimizations.md:240-250 [C]).
- hybrid-sw-block-promote (P:...:1-60): per-token-head quantized KV breaks the bf16 coincidence (4x256 vs 8x128 both 4096 B/token/layer); drafter's 5 layers took 385 blocks at 1.88% utilisation (5.155 GiB); patch rounds their block up to a divisor of the primary block (16 -> 864; 128 under KVarN): int8 pool 6.82 GiB@32k -> 138,696 tokens.
