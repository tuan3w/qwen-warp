# kv-pointer-draft-potential

## Question

The model's per-step state already encodes what it is copying. Can drafts read from that stored state (R1: where the 16 full-attention layers x 24 q heads attend in the context; R2: cosine kNN over the stored hidden states of every earlier position, incl. intermediate layers and key-like projections) add speculative acceptance beyond what K11's exact n-gram tail (R0: n=2 longest suffix match of the MTP chain end, agreement >= 3, tail <= 4 rows after the k=3 chain, T <= 8) already gets, on E6's 32 greedy tasks (`experiments/2026-10-31-ngram-draft-potential`: a code edit 8, b logs 6, c agent turns 6, d prose 6, e math 6; negative controls d/e)? And what would the engine need (device-side top-1 pointer from an attention epilogue; hidden store + cosine search: ms per cycle at 8K / 32K)?

## Prediction

Frozen in the frontmatter (commit `6981556`, before any engine run). Short form: R1 vote-ensemble coverage at precision 0.9 a .55 / b .50 / c .65 / d .04 / e .15 (below R0's l>=3 coverage everywhere); MTP+R1 / MTP+R0 = 1.01, MTP+R2 = 0.99, best-of = 1.03 [1.01, 1.06]; d/e not lost; >= 5 fuzzy-copy examples; recommendation NO (P=0.7); cosine search 0.10 / 0.40 ms per cycle at 8K / 32K. Scorecard in Results §11.

## Method

**What is measured vs modelled.** MEASURED on the real engine: the probe (the model's actual attention scores / masses / pointers at every decode position, teacher-forced on E6's canonical greedy continuations), the final-norm / intermediate hidden states, the K cache, the probe-vs-kernel agreement, the cost of the probe kernels and of a cosine search. MODELLED: every tok/s number (measured acceptance of each retriever's drafts against the real continuation x K11's **measured** cycle cost V(T=1..8) at ctx 64 / 2048 / 8192 (`experiments/2026-11-01-pld-tail-engine/results/cost_*.json`, interpolated per task context) via K11's `policy_sim.walk`); no R1/R2 policy was run inside the engine.

**Private engine.** `git archive HEAD` of `engine` (2d16e21, bf16 KV, K9 int4 head unused: `head=2` = final norm only) built privately in `~/llm-lab/e7_engine` with `engine_patch/probe.cu` (+ 3 hooks applied by `engine_patch/apply.py`). Nothing under `engine/src|include|spec.py|engine.py` was touched. After the K2 attention step of every full-attention layer (non-graph decode steps only) the probe re-reads the engine's own state: the normed + roped q that the K2 prep kernel leaves in its workspace and the bf16 KV cache (partial rotary is already applied to both), recomputes s_j = q.k_j/16 in fp32 for every key j <= pos0+t of every q head (GQA 6 q heads per kv head) and records per (row, layer, q head) the top-4 key positions, their softmax masses, the mass of position 0 (attention sink) and of the last 8 keys. Hidden states: debug taps 16/32/48/60/65 (residual stream after layers 15/31/47/59, final norm out) of every position (prompt included) are copied into a bf16 store on the GPU; the K cache (dims 64..255 = the non-rotary part, 4 kv heads = 768-d) of attention layers 7/11/15 (model layers 31/47/63) is the key-like representation.

**Frame (everything implementable at drafting time).** Cycle i has anchor g_i (E6 trace). The row that produced the anchor (absolute index P+i-1) is the freshest stored state a drafter can read for free (it is also the MTP head's input). A *source* s is the position holding the copy of the anchor (token[s] == g_i, anchor-consistent): for head pointer q, s = q + o (o in -2..2 fitted per head on training tasks: o=0 'the attended token is the answer', o=+1 'the attended token precedes it'); for kNN neighbour j, s = j+1. Draft slot k = token[s+k] over known tokens (prefix up to the anchor, then the MTP drafts d1..d3; unknown -> no draft); slots 1-3 are the chain's, slots 4-7 the tail. R1 source = mass-weighted vote of the selected heads' top-4 pointers (mass >= 0.03, anchor-consistent), confidence = summed mass; R2 source = best neighbour among positions whose next token equals the anchor, confidence = cosine (cosine on raw, prompt-mean-centred or prompt-mean-centred-then-normalised states). Teacher forcing: the full E6 sequence is run once through the engine in T=4 steps (prompt as graphs, decode rows non-graph with the probe); the F stream of E6 (`trace.npz`) is the canonical continuation (8 of 32 tasks differ from E6's natural stream after 98-711 tokens, as E6 documents).

**Calibration / evaluation.** Everything fitted (head subset and offsets, confidence thresholds for precision >= 0.9 on the first draft, policy gates = min agreement with the MTP drafts x confidence quantile, replacement thresholds) uses one half of the tasks and is evaluated on the other (2-fold, stratified by class, alternating tasks); CIs are task-bootstrap (2000 draws, stratified by class). Gates are class-agnostic (one threshold for a-e, as an engine would have). The per-head table, the oracle bounds and the comparisons that carry no fitted parameter are in-sample / hindsight and labelled so. R0 = `policy_sim.prep_tail` with K11's defaults.

## Results

All numbers: `results/tables.md` (full tables), `results/summary.json`, `results/probe_check.json`, `results/micro.json`, `results/examples.json`. 20,000 cycle starts (a 5,296; b 3,538; c 2,126; d 4,438; e 4,602).

### 1. The probe measures the real model (MEASURED)

Torch recompute (fp32 softmax over the engine's own bf16 KV, q and gate snapshots, `sigmoid(gate)`) vs K2's output `y6`, 16 attention layers x 12 probed T=4 steps (4 tasks, contexts up to 5K): **rel L2 per layer 1.66e-3 .. 1.72e-3 (mean 1.695e-3), worst single (step, layer) 2.03e-3**. That is the bf16 floor, not a semantic difference: torch's own bf16 SDPA vs the same fp32 recompute is 1.66e-3. Probe top-1 key == torch top-1 at 100% of (step, layer, head) cells, max |mass error| 2.4e-4, sink mass error 2e-4. So the criterion (< 2e-3) holds on every layer's mean and misses it by 2% on the single worst cell.

### 2. Which heads point at the copy source (R1, in-sample, descriptive)

Rank-1 non-sink pointer of the producing row: P(token[q+o] == anchor) per head. Best heads: layer 59 head 21 (o=0) 0.586, layer 47 head 19 0.503, layer 63 head 9 0.473, layer 19 head 10 (o=+1) 0.475, layer 3 head 23 (o=+1) 0.458; of those anchor-consistent rows 75-83% have the right next draft. 34 of 384 heads have cons > 5% and first-draft precision > 0.8; they concentrate in the last attention layers (attn idx 12-15: 7 / 3 / 3 / 12 heads) plus a few early ones; offsets of the good heads: -1: 9, 0: 12, +1: 12 (so 'token at the attended position' and 'token after it' are both used, by different heads). Top-20 table: `results/tables.md`. So attention does carry a copy pointer, in many heads.

### 8. Where the MTP chain is wrong

MTP chain run < 3 at a 12.5% / b 12.4% / c 3.1% / d 74.8% / e 26.7% of positions. A confident R1 (calibrated gate) issues at 140 / 96 / 20 of those cycles in a / b / c and is right at the first missed slot in 39% / 43% / 25% of them (d 8%, e 20%): it fixes slot rm+1 in 8.1% / 9.4% / 7.7% of the MTP-miss cycles (a/b/c; d 0.4%, e 2.7%). Using the pointer to *replace* the chain when it is confident and disagrees with MTP gives x1.358 vs R0's x1.359 pooled (the held-out selector chose 'never' in one fold and a 95% quantile cut in the other; replacement used in 0.1-0.6% of cycles, pointer run beats chain in 52% / 20% / 17% of those in a / b / c). R0 cannot fix chain errors by construction (tail only after a full chain).

### 10. Costs of the machinery (MEASURED where stated)

- **Probe kernels as a separate pass (my unfused probe, measured, a8 ctx 5.6K, non-graph step): +0.85 ms at T=1 (17.87 -> 18.72), +2.4 ms at T=4 (19.08 -> 21.50)** = 4% / 11% of a cycle: an upper bound on a naive implementation (3 launches x 16 layers, scores re-read through global memory), not a design.
- **Cosine search of one query against L stored 5120-d bf16 states (`torch.mv`, measured): 0.031 ms at 2K, 0.105 ms at 8K (84 MB, 0.8 TB/s), 0.42 ms at 32K (336 MB), 0.81 ms at 64K; with next-token masking + argmax 0.043 / 0.118 / 0.442 / 0.840 ms** = 0.5% of a ~21 ms cycle at 8K, 2% at 32K (bandwidth bound; an fp8 store would halve it; the store costs 10 KB per position (bf16) vs 64 KB of bf16 KV per position, written by 5 D2D copies of 10 KB per row here, one fused epilogue in practice).
- **Top-1 pointer epilogue inside the attention split kernel: NOT built, estimate only [INFERENCE]**: the split kernel already computes the scores and the running max per warp/column (`attn.cu` `compute`: `mx0/mx1`, `m_run`); an argmax needs a (value, key index) shuffle pair or ballot on the same data, one int per (split, head) next to `ml`, and the reduce kernel's merge gives the global argmax and its mass (= 1/L when the best key is the global max). The 16-layer attention step is 0.78 ms (T=1) / 0.88 ms (T=4) at 8K bf16 KV (K11 `bench_attn.log`) = 4% of a cycle, so even a +25% slower attention costs ~1% of a cycle; plus a 384-head vote kernel (<10 us).

## Conclusion

**Answer.** The model's attention does know where it is copying from: 34 of 384 heads (mostly the last attention layers, offsets -1 / 0 / +1) point at the anchor's source, and a head vote predicts the token it just wrote about at precision 0.91-0.96 on 68-75% of positions of the copy classes, as often as an exact 3-gram match; the final hidden state's nearest neighbour does it at 0.92-0.99 precision at 12-32% coverage. But that is the *same* information exact lookup already has: over K11's MTP chain + exact n-gram tail (modelled with K11's measured cycle costs, which reproduce its measured A/B within 1.6%), the pointer tail alone is **x0.965 [0.949, 0.980]** on a-c, hidden-state kNN x0.880, **the best-of combination x1.000 [0.998, 1.003]** (d 0.998, e 0.997), the pointer-replaces-the-chain variant x0.999, and even a hindsight oracle over all three retrievers reaches only x1.010 [1.002, 1.018]. The information bound is why: with perfect selection among every earlier occurrence of the anchor token the headroom beyond K11's tail is x1.043 [1.030, 1.053] on a-c (+0.2..+0.5 accepted tokens per cycle); the attention pointers hold essentially all of it (x1.040), but head masses are a worse selector than the exact agreement with the MTP chain that R0 uses. Fuzzy copies (renamed identifiers, changed numbers in a table row, edited docstrings) are real (examples above) but are 1% of positions and sit where the MTP chain is already wrong, where an appended tail cannot use them; replacing the chain does not pay.

**Recommendation: do NOT implement R1 (device-side attention pointer) or R2 (hidden-state store + cosine search) as additional drafters on top of K11's exact tail.** Expected gain +0.0% (CI [-0.2, +0.3]) a-c, <= +1% if everything went right, vs engine complexity and a cost floor: R2 = a hidden store (10 KB per position, +0.8 GB at 80K tokens) + a bandwidth-bound cosine kernel (0.105 ms at 8K, 0.42 ms at 32K per cycle = 0.5% / 2% of a cycle, i.e. a pure cost when it adds nothing); R1 = an argmax epilogue in the K2 split kernel + per-layer (idx, mass) outputs [16][T][24] + a vote kernel + a host/device gate: cheap (est. <1% of a cycle, not built) but with nothing to gain.

*If a pointer drafter were still wanted* (e.g. for a workload dominated by fuzzy templates with no exact repeats, which E6's 32 tasks do not contain), the exact changes are: (1) K2 split kernel (`attn.cu` `attn_split_kernel::compute`): carry (best score, key index) per warp/column next to `m_run/l_run`, merge across the KS warps in the existing smem merge, write idx next to `ml` ([kv head][split][col] int); (2) reduce kernel: pick the split with the global max, write per (row, q head) (idx, mass = 1/L) into a [16][T][24] buffer (only the last accepted row's slice is read); (3) a small vote kernel at the end of the verify graph: heads with fitted offsets (from `results/summary.json` `heads.top`, 34 heads), anchor-consistency against the token ring, source -> tail tokens written into the draft buffer (needs the K11 tail slots + the on-device accepted-row index); (4) hidden-state variant only if the store is free: final-norm rows written by the existing head-tail kernel into a [ctx][5120] bf16 ring and one `mv` + masked argmax per cycle.

**Not shown / caveats.** (i) Modelled throughput (also not run: R0/R1/R2 on FP8 KV, sampling): no R1/R2 policy was run in the engine (V(T) and the MTP/tail cycle structure are K11's measured values; acceptance of the retrievers' drafts is measured offline against the real continuation); (ii) 32 tasks, 6-8 per class, one repo, one model, greedy only (E6's caveats apply: class c has three very short outputs, d/e prompts are short so there is little to copy); (iii) R0, R1, R2 gates are class-agnostic and fitted on half of the tasks (2-fold CV); the precision-0.9 thresholds do not transfer to prose / math (precision 0.52 / 0.75), the oracle bounds are in-sample/hindsight; (iv) pointers are read from the 16 full-attention layers only (the 48 DeltaNet layers keep their recurrent state in a form that has no position index; not read) and from the single row that produced the anchor ('stale' by design: the anchor's own row is only computed in the verify step it feeds); (v) teacher-forced T=4 steps vs E6's cycles: rounding near-ties can change hidden states by bf16 noise, not the stored positions; (vi) bf16 KV only: FP8 KV (the server default) would add dequantisation noise to the scores, not studied; (vii) top-4 pointers per head with mass >= 0.03 and offsets -2..2; richer selectors (a learned scorer over head masses) were not tried beyond the vote + agreement gate, the oracle says there is at most +4% to find; (viii) K11's tail itself is a post-hoc E6 cell, so 'R0' is a strong baseline by construction.

## Dead ends

- **Hidden-state kNN at intermediate layers and middle keys (layers 48/32, keys 47/31)**: centred, raw, z-scored or normalised-then-centred cosine never reaches 0.9 first-draft precision at any threshold (the residual stream at those depths mostly encodes the current token and position, not the next one); the z-scored / normalised variants (second collect) change the final-norm and layer-60 results by < 0.02 coverage.
- **Calibrating a vote by summed mass**: coverage at precision 0.9 is non-monotonic in the number of heads (top-4 .42 pooled a-c, top-16 .17, top-384 .035) because the sum scales with M; I did not search for a normalisation (the policy-level and oracle-level results do not depend on it).
- **Pointer next token without the anchor** is a different question from drafting after the anchor: it looks impressive (precision 0.96 at 68% coverage, a) but the anchor is already known, so it adds nothing; the drafts need the *continuation* of the source, which head mass does not certify.
- **Replacement of the MTP chain** by a confident pointer that disagrees with MTP: the throughput-tuned selector chose 'never' in one fold; the other fold's gain does not transfer (x0.999 pooled).
- **Process mishaps (no effect on the data)**: the first collect launch died with the tool's background job (restarted detached; the probe is deterministic so the first two tasks were reused); the second collect (z-scored variants) was first launched in a command chain whose lease acquisition failed (the lease was held by another job) but the chain continued: the process died at weight load with a CUDA OOM (the other process had 19.6 GiB) before any kernel of mine ran, then was replaced by a script that waits for the lease and checks the acquire exit code; the second collect (10:01-10:11) reproduced every number of the first bit-for-bit (all R0 / R1 / old R2 tables identical, the CI draws too) and added the z-scored / normalised variants, so `results/` is from it; a name clash between this experiment's `analyze.py` and E6's was avoided by importing E6's through `sys.path` order.
- **Not done**: no engine A/B of an R1/R2 drafter; no sampling mode; no FP8 KV; no learned selector; the epilogue cost is an estimate.
