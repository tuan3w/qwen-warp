# tpu-megakernels

Inferact's Pallas/TPU "megakernel" decode for Qwen3.8-27B (BF16, hybrid 48 gated-DeltaNet + 16 GQA, 64 layers) + DFlash2 block-diffusion speculative decoding; also Kimi K3 and Muse-Spark (not studied beyond quantised-tile precedent). All paths below are relative to `vendor/tpu-megakernels/` at `a120ca4`. Tags: `[read]` = read in code, `[INFERENCE]` = my arithmetic/extrapolation, nothing here was run (no TPU; no builds).

## Why I cloned it

Planning a persistent fused decode kernel for Swift-1.5-Qwen3.8-27b-INT4 (W4A16 g128, Qwen3.5 arch, 1 MTP layer) on one RTX 3090 (sm_86, 936 GB/s), vLLM-integrated. Questions: (1) how one kernel holds a whole hybrid decode step + weight streaming; (2) multi-token DeltaNet verify and rollback; (3) what of DFlash2 spec-decode transfers to MTP on one GPU; (4) what the headline numbers actually measured; (5) per-token bytes; (6) reusable correctness oracles; (7) failure modes.

## Mechanisms

### 1. "One kernel" = one `pallas_call` per token (or per 8-token block), statically scheduled — not a task graph
- A decode step is a single `pl.pallas_call` (`qwen/decode_megakernel.py:974-991`, name `qwen_transformer_stack`) with all weights in HBM (`memory_space=tpu.HBM`, 978-981), states aliased in place (`input_output_aliases` 977), 64 MB VMEM limit (986). The 64 layers are a `lax.fori_loop` over a *single traced layer body* with `lax.cond(li % 4 == 3, full_attention, linear_attention)` (808-812, 850) — not unrolled, no task queue/instruction stream. Order is hard-coded: `norm_in -> mixer -> allreduce+residual -> norm_post -> MLP -> allreduce+residual` (808-812). [read]
- Multiple tokens per host call are a `fori_loop` of such kernels on device (`demo_qwen_dflash.py:216-225`, `--steps-per-call` default 256, `scripts/benchmark_qwen.sh:26`); spec decode = `while_loop` of [draft kernel, verify kernel, XLA accept/rollback glue] (`qwen/dflash.py:1403-1485`). So a spec round is 2 Pallas kernels + small XLA ops, not one kernel. [read]
- Fusion inside a layer (all intermediates stay in VMEM scratch, 897-972): RMSNorm (zero-centered, `1+w`) computed from the resident residual (569-580); in-proj of DeltaNet fuses `[q|k|v|z|b|a]` into ONE gemv via packed columns (`load.py:154-168`, zba "rides along as extra output columns"); full-attn fuses `[q+gate | k | v]` (`load.py:135-144`); MLP fuses `[gate|up]` into one gemv (`load.py:120-129`), then SiLU*mul in-register (803-804) feeding down-proj. `attn_output_gate` sigmoid-gate multiply and the DeltaNet `rms_gated`*silu(z) are applied in VMEM before the out-proj gemv (791-793, 662-672). Residual add is fused with the cross-rank reduction (`exchange_add` 563-567). Final norm + LM head + greedy argmax (per-rank argmax then (val,idx) pair exchange) are in the same kernel (854-893), so logits never leave the chip except for debug. Embedding row fetched by DMA inside the kernel (821-849). [read]
- **Weight streaming = one global flat tile stream with cross-op, cross-layer lookahead.** `schedule()` (`load.py:229-267`) lists per-layer-family matrices with (bk,bn) tiles (caps 1024x1280, `tile_hw` 270-278, env `QWEN_MAXK/MAXN`); weights are physically re-laid-out so each tile is contiguous in HBM (`tile_matrix` 281-288). A global tile index `g` maps to (layer-block, matrix, tile) by static offsets (`fetch`, `decode_megakernel.py:468-515`; 4-layer block of 3 linear + 1 full = `t_block`, 267). A ring of `BANK_COUNT=12` VMEM tile slots (27) with one DMA semaphore per slot (922-923): `gemv` waits tile `ti`, does the MXU dot, then immediately issues tile `base+ti+BANK_COUNT` (517-537, line 533) — the lookahead index is global, so the next op's/next layer's/LM-head's tiles are already in flight while the current op finishes (queue never drains between ops). Prologue primes the first 12 tiles before the cross-device barrier (831-838). The ring is ~12 x (1024x1280x2 B = 2.6 MB) ≈ 31.5 MB in flight per device. [read; the 12 and tile caps are env-tunable defaults, tuning data not in repo]
- Non-weight DMAs are overlapped manually: DeltaNet conv/state/conv-weights/a_log/dt_bias/norm loads are *started before* the in-proj gemv and waited just before use (605-611, 616-618, 647-653); state write-back DMAs are started right after update and only waited at the next DeltaNet layer's entry (599-602, 641, 660) or kernel end (852-853); next layer's norm vector is prefetched into the same slot (578-580). [read]
- GQA decode attention (675-766): per KV head, 128-row K/V tiles double-buffered from HBM (`kb/vb` (2,128,hd), 954-955), online-softmax (m,l,acc) flash loop over `pos//128+1` tiles, Q group (<=8 heads) padded to one 8-row MXU tile (676-679, check 363-364), current token's K/V patched into the resident tile then the whole tile DMA'd back (704-714). Causal + left-pad mask `slot<=pos & slot>=key_lo` (725-730). KV is BF16 (`initial_states` __init__.py:198-204), not FP8. [read]
- TP split (load.py:97-202): heads/channels aligned, TP8; 4 KV heads on 8 ranks => each KV head pair-replicated on 2 ranks (`load.py:110-115`, test `tests/test_qwen_decode_cpu.py:145-163`); vocab sharded for emb/LM head (`load.py:101-104`). Two collectives per layer implemented as hand-rolled all-to-all remote DMAs (`make_async_remote_copy` to `rank^offset`, decode 539-561: broadcast fp32 [1,h] partials and sum locally; verify 1219-1267: reduce-scatter in fp32, round once to bf16, all-gather bf16). [read] -> 128 collectives/token; TPU/TP-specific.

### 2. DeltaNet single-token and 8-token verify (no chunked form in the kernel)
- Per-token recurrence (kernel 654-659, oracle `delta_step` `__init__.py:169-172`): `S <- S*exp(g)`; `pred = S k`; `S <- S + ((v - pred)*beta) (x) k`; `o = S q` with S fp32 `[v_heads_r=6, 128(v), 128(k)]` per rank (store transposed [value,key] "so both contractions reduce over the minor axis", `__init__.py:146-147`; 939). `g = -exp(a_log)*softplus(a+dt_bias)`, `beta = sigmoid(b)` rounded to bf16 (644-645); q/k l2-normed (eps 1e-6), q scaled `k_dim**-0.5`; k-heads(16)->v-heads(48) by repeat x3 (634-640). Conv: depthwise width-4, state = last 4 *raw* qkv inputs `[conv_dim,4]` bf16 (620-627, `__init__.py:258-269`), silu after. Decode implemented with VPU elementwise `sum(S*k, -1)` over VMEM `sbuf` — the MXU is not used for the state update. [read]
- **Verify block (B=8: anchor + 7 drafts) is a plain sequential loop of 8 single-token updates**, Python-unrolled in the kernel (`for t in range(B)` 1359-1377): same math per t, conv done as one batched 4-tap sum over a `[4+B, qkvw]` window (1326-1332). No WY/UT-transform/chunk form; the chunked algorithm (`chunk_gated_delta_rule`, C=64, triangular_solve `__init__.py:308-341`, a port of HF `torch_chunk_gated_delta_rule`) is used only in prefill. The pure-JAX verify reference is also sequential: `delta_rule_block` = `lax.scan` returning per-step state snapshots (`__init__.py:468-494`). Cost model: 8 serial passes over the 393 KB/rank fp32 state per layer, hidden under the weight stream. [read]
- **Rollback by snapshotting every intermediate state:** after each t the fp32 state is copied into a 2-slot VMEM staging buffer and DMA'd to `recsnap[ord, t]` in HBM (1374-1377, wait for slot reuse 1360-1364); conv snapshots store the 4-tap input window per t (`convsnaps[t*4+tap]=xp[t+1+tap]` 1333-1335, DMA 1380). The kernel's aliased conv/rec outputs hold the post-block (all-8) state, which is discarded (docstring 1002-1003). XLA glue then picks the accepted index `acc`: `rec = snaps["rec"][:,:,acc]`, conv = dynamic_slice of rows `acc*4..+4` transposed (`dflash.py:1313-1323`, same in scan 1442-1450). Index semantics: row t holds the state *after* consuming token t of `[anchor, d1..d7]`; `acc` = number of leading draft matches (`cumprod(block[1:]==post[:-1])`, 1310-1311), `bonus=post[acc]` becomes next anchor (unconsumed), `produced=acc+1`. [read]
- KV needs no rollback: verify writes K/V for all 8 slots positionally (`kb8/vb8` patch + tile write-back, 1393-1463; straddling two 128-row tiles handled 1425-1463) and un-accepted slots are overwritten next round (`make_verify` docstring 192-193); in-block causality via `keep_g = slot <= pos0 + row_query_index` (1465-1467). Left-pad rows are made recurrence-identities (`beta=sigmoid(-1e30)=0`, `a=-1e30 -> gate=0`; `decode_megakernel.py:124-125`, `__init__.py:357-359`) and masked in attention via `key_lo`. [read]
- The 8 query rows ride the MXU for free: decode `gemv` broadcasts the single activation row to an (8,bk) tile (527), verify uses the real (B,bk) tile (1207). Same weight bytes for 1 or 8 rows. [read]

### 3. DFlash2 speculative decoding
- Drafter: **non-autoregressive block-diffusion draft, one forward pass for the whole block** (`dflash.py:1-12`, `draft_forward` 160-181): input = embedding (shared with target) of `[anchor, MASK x7]` (B=`block_size`=8, `mask_token_id`); context = target hidden *taps* from 5 layers (default `tap_layers=(5,19,33,47,61)`, `decode_megakernel.py:186`, = `dcfg.target_layer_ids`) concatenated (5*5120) -> `fc` -> `hidden_norm` (169-171). The kernel comment says "the 5 draft layers" (`dflash.py:941`; tiny test cfg has 2, `tests/test_qwen_dflash_cpu.py:42`; real draft width/heads/params NOT in repo — they live in the HF checkpoint config). Each draft layer: input RMSNorm -> **dynamic grouped 2-tap conv** (`conv_prepare`/`conv_finish`, 60-86; kernel = base_kernel + token-dependent projection) -> QKV where K/V of *context rows* come from `ctx @ k_proj/v_proj` and K/V of block rows from `hn @ k_proj/v_proj` (123-133) -> bidirectional sliding-window attention over ctx+block (136-145) -> out-proj -> conv -> residual -> same conv-sandwiched SwiGLU MLP (151-157). Final norm, then the **target's own LM head** on the 7 draft rows (184-186; kernel 1059-1090). [read]
- Candidate selection (the "path"): per row top-K (K=`selector_top_k`) from target-LM-head logits; then a greedy 7-step chain scores `unary + successor_codebook[cand] @ (predecessor_codebook[prev] * hidden_proj[i])` with rank-R codebooks (`select_path` 189-206; kernel 1092-1186). I.e. a learned low-rank pairwise (CRF-like) term makes the 7 tokens jointly consistent rather than 7 independent argmaxes. K/R values are in the checkpoint config, not the repo. [read]
- Rows: 1 anchor + 7 drafts = 8 verified rows = exactly one MXU sublane tile; max `produced` per round = 8 (acc=7 + bonus). Greedy-only; lossless w.r.t. target greedy by construction (`dflash.py:6-7`, `match = block[1:]==post[:-1]`). [read]
- No draft KV cache: each round re-streams the ctx window from `ctxbuf` (projected target features, double-buffered 128-row tiles) and recomputes K/V for the whole sliding window through `kv_proj` (`dflash.py:984-1006`); the previous round's 8 verified feature rows are projected (`fc`, streamed in 64-row chunks, psum, `hidden_norm`) and folded into `ctxbuf` in the draft kernel's prologue (`dflash.py:841-888`; `make_round_fn_kernel` doc 1361-1372). Taps are written by the verify kernel into `taps_out` at the 5 layers (`decode_megakernel.py:1573-1582`) and into `featbuf` (`dflash.py:1324-1325`) — zero host involvement. [read]
- Acceptance claims: **there is no measured acceptance in this repo.** The only Qwen spec number uses synthetic acceptance `--force-accept 5` ("acceptance length 6", `scripts/benchmark_qwen_dflash.sh:26,70`; "bypasses real acceptance; for perf measurement only", `demo_qwen_dflash.py:132-135`; `force_acc` `dflash.py:1415-1417,1440`). Real tokens/round is only printed by the demo (`demo_qwen_dflash.py:462-465`). Correctness of spec output is checked by `--baseline` greedy compare (demo 5-7, 466-480) and the GSM8K/GPQA harness scripts (`scripts/eval_qwen_gsm8k.sh`, `eval_qwen_gpqa_diamond.sh`). [read]

### 5. Per-token memory traffic (my arithmetic from `qwen/__init__.py:15-31`; nothing measured)
- Weights read per decode step ≈ 25.6 B params ≈ **51.2 GB BF16** (per layer: MLP 3x5120x17408 = 267.4 M; DeltaNet in/out+conv ≈ 115.9 M; full-attn ≈ 104.9 M; LM head 1.27 B; embedding contributes one row). 6.4 GB per TP8 rank. Every layer's weights are read once per step regardless of block size 1 or 8.
- DeltaNet state: 48 layers x (48x128x128 fp32 = 3.15 MB) = 151 MB read + 151 MB written per step (0.6% of weights). KV: 16 layers x 2 x 4 heads x 256 x 2 B = 64 KB/token of context (BF16; ~2x on TP8 due to pair-replication). At ctx 1000: 64 MB.
- Verify-round extras: rec snapshots 8 x 151 MB = **1.21 GB written/round (≈2.4% of weight bytes)** + conv snaps + the XLA select-copy of the accepted rec state (151 MB r/w) + discarded post-block state write-back. Draft extras: LM head re-read for 7 rows (≈2.5 GB bf16, ~5%) + 5 draft layers + ctx-window K/V recompute (sizes depend on unseen checkpoint config).
- Padding waste: DeltaNet in-proj columns `[qkv 1280 | z 768 | b,a 12 | zero pad 500]`, per rank 2560 wide with 500 zero columns DMA'd because `zba_pad` rounds to 640 (`load.py:205-216`) => ~245 MB/rank ≈ 3.8% extra HBM bytes [INFERENCE from formula]; gu/dw/LM pads are bounded to ≤6% (`load.py:291-326`).
- For our 3090 (INFERENCE, my arithmetic): if all but LM head are W4 g128 (+bf16 scales) ≈ 12.6 GB + bf16 LM head 2.5 GB = 15.1 GB → ~62 tok/s plain roofline at 936 GB/s; if LM head also int4 ≈ 13.2 GB → ~71 tok/s. Spec decode multiplies by tokens/round only if verify of 8 rows stays weight-bound.

### 7. Lessons and failure modes found in comments
- Stale scratch is a NaN hazard: masked attention positions are `0 * stale`; zero the K/V scratch each round or NaN/Inf poisons the draft (`dflash.py:931-938`). Analogue for us: any masked/skipped-tile read must be finite.
- DMA semaphore waits count completions, not identity: "the m-th wait only guarantees m total completions, so reading row m before the last wait can race" -> start all, wait all, then read (`dflash.py:1148-1150`).
- HBM refs are (8,128)-tiled, so dynamic row writes must be 8-aligned: read-modify-write a 16-row block with a one-hot matmul for the shift (`dflash.py:872-886`; `ctxbuf` needs 16 trailing dummy rows, doc 636-637). TPU-specific.
- Compiler fragility: Mosaic corrupted residual snapshots across loop iterations when a scratch allocation was shrunk to 2 rows (`kimi/decode_megakernel.py:5087-5093`); every Pallas call sets `disable_bounds_checks=True` and `shape_invariant_numerics=True` (`decode_megakernel.py:984-989`) so 1-row and 8-row paths give shape-invariant arithmetic; all launchers set `XLA_FLAGS=--xla_allow_excess_precision=false` (`scripts/demo_qwen_dflash.sh:37`).
- Numerics are schedule-sensitive and gated by eval, not by unit test: a 512-wide flash block was faster but moved GSM8K strict-match to 0.9500 vs 0.9515 for the 128-block schedule, so they kept 128 (`mpk/decode_megakernel.py:326-329`).
- Profiling by ablation: kernels carry `ablate` flags (`noexchange`, `nodelta`, `noattn`, `noaux`, `nocompute`) that remove one stage while keeping the weight stream (`decode_megakernel.py:564,604,615,716,1270,1358,1469`) — time attribution of compute vs DMA vs collective without a profiler. Bank count / tile caps are env knobs (`QWEN_NB/MAXK/MAXN`, 27-29) for sweeps.
- Layout rules baked into asserts: `layers%4==0`, `head_dim==256`, `context%128==0`, GQA group ≤ 8 rows (347-364); `--context` multiple of 256 and ≥512 (`demo_qwen_dflash.py:141-142`); prompts left-padded to a chunk multiple with `key_lo=npad` (`demo_qwen_dflash.py:246-258`).

## Transferable to a single-3090 CUDA megakernel
- Static weight-tile stream with *global* lookahead: pre-tile weights so each tile is contiguous, flatten all matrices of all layers into one tile index, keep an N-deep async-copy ring that crosses op and layer boundaries, and size depth from bandwidth-delay (their 12 x 2.6 MB). On sm_86 this is `cp.async` rings in smem (no TMA) feeding mma; the idea that the DMA queue never drains is the core win.
- Fusion boundaries (norm→fused in-proj [q|k|v|z|b|a]/[gate|up]→gate/silu→out-proj→residual; LM head + argmax in-kernel; embedding row fetched in-kernel). Same layer ordering and per-op state prefetch/lazy write-back for DeltaNet conv/rec state and norm vectors.
- Verify B rows through one weight pass: weight bytes identical for 1 vs 8 rows; on tensor cores M=8-16 rows is one mma tile so the dequant+stream cost is amortised (the same property they exploit with 8-row MXU tiles).
- DeltaNet verify as sequential per-token updates with per-token state snapshots, accept index selects snapshot; KV overwritten positionally with in-block causal mask; left-pad rows as identity updates.
- On-device speculative loop (draft→verify→accept→rollback in a device-side while loop, 256 rounds per host call, taps/features never leave the device) — directly maps to a CUDA graph/persistent loop and to vLLM's MTP flow if we expose accept/rollback buffers.
- Oracle layout: BF16 rounding points of `qwen/__init__.py` + chunked-vs-recurrent DeltaNet test; eval-gated numerics (GSM8K 100-sample) for any schedule change; ablation flags for attribution.
- Quantised-tile precedent: Kimi's FP8/MXFP4 path dots raw low-bit tiles per scale block and applies the scale to the fp32 partial (`kimi/decode_megakernel.py:304-332`; trade-off note 297-300) — the same shape as g128 symmetric int4 (dot per 128-group, scale post-mma).

## TPU-specific (do not port)
- TP8 + 128 hand-built remote-DMA all-reduces/token and the pair-replicated KV; the vocab-sharded LM head and cross-rank (value,index) argmax. One 3090 has none of this (TP=1) — but also loses the free sequential ordering: a GPU persistent kernel needs grid-wide barriers between dependent ops (the TPU kernel gets ordering from a single in-order TensorCore per device).
- Pallas/Mosaic mechanics: VMEM 64 MB budget, (8,128) HBM tiling, 128-multiple tile/pad rules (`zba_pad`, `lm_pad`), 8-row MXU tile broadcast, `make_async_copy` semaphores, unrolled-Python layer pieces, `shape_invariant_numerics`.
- BF16 (unquantised) weights; no W4 path for Qwen at all (quantised tiles exist only for Kimi/Muse).
- DFlash2 specifics: 5-layer bidirectional-window drafter conditioned on 5 target taps and dynamic conv, learned pairwise path selector, 8-row block: needs a bespoke trained draft checkpoint (`z-lab/Qwen3.8-27B-DFlash2`, README.md:76). Our MTP head (1 layer) is autoregressive-depth-1 per call, so acceptance-length-6 per round is not a transferable number.
- The MXU-free VPU DeltaNet update: fine in VMEM on TPU; on GPU use registers/smem + warp reductions.

## Worth stealing — 5 ideas to test first

## Gotchas
- Do not read "persistent megakernel" as an instruction/task-queue interpreter: the Qwen path is a statically ordered layer loop with one ring of weight tiles; scheduling is the compile-time `schedule()` (`load.py:229-267`).
- Headline 1,515 tok/s: synthetic acceptance, ISL=1, 4 TPU v7 chips, BF16; plain Qwen throughput and real acceptance are absent; the batch-1..8 bars and the AL3 bars are Kimi.
- The block-verify kernel and DFlash draft kernel are TPU-only and untested on CPU; `make_verify` (186-342) is a JAX twin but is not exercised by `tests/`.
- Draft model size/heads/top-K/rank are only in the HF checkpoint config; any DFlash2 cost estimate from this repo is incomplete.
- Source `vendor/` is read-only; if we reuse oracle code copy it into an experiment and note changes.
